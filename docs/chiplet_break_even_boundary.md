# Chiplet Break-Even Boundary

Date: 2026-08-14

## Question

The current architecture candidate is a schedule-aware MLP fabric with dense
attention and dense fallback. This note asks a narrower question: when can a
chiplet realization beat an equal-resource monolithic fabric after paying
activation-link, router, and synchronization overhead?

## Model

The Qwen3-4B/DFlash-b16 dimensions and the calibrated width-aware cost model
are used:

- block size 16, five draft layers;
- attention MAC approximation 26.2M per layer-position;
- MLP MAC approximation 74.7M per layer-position;
- 4096 activation bytes per position;
- multicast reuse 4;
- synchronization 20 cycles;
- router cost 0.25 cycles per position;
- link bandwidth 128--1024 bytes/cycle.

The monolithic and chiplet paths have the same aggregate compute capacity. For
each point, the break-even parallel gain is

```text
G_break_even = (chiplet_compute + link + router + sync) / chiplet_compute
```

A chiplet design must provide an effective specialization/utilization gain
larger than `G_break_even`; merely partitioning the same compute resource is
not sufficient.

## DAC implication

This gives chiplets a precise conditional role:

- **Kill chiplet specialization** if it only moves the same aggregate compute
  and cannot demonstrate the required gain after routing and synchronization.
- **Promote chiplets** only if an equal-area/energy model or a measured queue
  experiment shows at least the boundary gain through parallel schedule-class
  service, lane specialization, or sharing benefits.
- Keep the grouped monolithic fabric as the reference architecture and dense
  fallback in either case.

The strongest paper claim is therefore not “DFlash needs chiplets.” It is:
**prefix-survival-aware schedules expose a measurable utilization opportunity;
chiplets are worthwhile only when physical specialization converts that
opportunity into more than the explicit traffic/synchronization overhead.**

The fixed-shape RTX 4090 measurements confirm that narrow MLP lanes have
compute-side headroom, but the corresponding acceptance schedule is a separate
gate. See [`docs/chiplet_specialization_measurements.md`](chiplet_specialization_measurements.md).
